Languages you know, for about 35 languages

GitHub issue #490. The list grows from three languages to about 35 (English, India's 22 scheduled languages, and twelve more), so a tick box per language no longer works. Three options follow, each as one screen used in both places (owner, 2026-10-12): first launch and Settings show the same body and differ only in the chrome around it (first launch: progress and a pinned Continue; Settings: app bar, back and Save). Every language shows its own name in its own script beside the English name. Targets are 48dp or more, the pinned bar sits above the system navigation bar (#489), the lists wrap rather than scroll sideways, and each option has a frame at 2x text. The keyboard is not drawn in the searching frames; the list area shrinks above it and the pinned Continue stays above the keyboard. The demo person is on an English-language phone set to India, and knows English, Hindi and Telugu.

Recommendation (best first)
  1. A, search first. Fewest taps for the common case (suggested chips), every language findable by either name, one screen for first launch and Settings, with the script question next to the language it is about. Main downside: someone who cannot spell the name must use "Browse all 35", a plain A to Z list, which has to be built as well.
  2. C, two steps. The best list, but it needs a second page in Settings, so it does not reuse as one screen. Main downside: extra step and extra work.
  3. B, grouped and folded. Good for browsing but needs the person to know our script families. Main downside: it hides the list behind six folds and costs the most taps.

One screen, two places. Whichever is chosen, build the body once. First launch wraps it in the onboarding header (step progress) and the pinned Continue; Settings wraps it in the app bar with back and Save. The body, the rows and the script questions are the same widget, so onboarding can later simply reuse the Settings page.
