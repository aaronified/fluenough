# Plan: load only the selected language at startup, the others when they are selected, and never on the UI thread

Source of truth: this wiki page.

Written 2026-11-22. Design only: no app code is changed by this page. Its decision record is [ADR-0062](ADR-0062-Per-Language-Catalog-Loaded-On-Demand). It builds on [ADR-0048](ADR-0048-Catalog-Snapshot) (the catalog snapshot), [ADR-0051](ADR-0051-Replay-Snapshot) (the replay snapshot), [ADR-0047](ADR-0047-Performance-Model) (per-language versions, batching), [ADR-0034](ADR-0034-Hear-Say-Write) (the skill map) and [ADR-0037](ADR-0037-Decks-Download-From-Main) (downloads).

Owner order, 2026-11-22: "Load only the language selected on startup (then load others when they are selected), not all of them. And not in UI thread."

How to read this page: every claim is tagged **FACT** (read in the code or the data at `origin/main` 555c3d333 on 2026-11-22, with its file and line) or **INFERENCE** (reasoned from facts, not measured; to be checked by the instrumentation of work package P-A). Line numbers are of that commit and drift; the symbol names do not.

## 1. The problem in one paragraph

A cold start lists and reads every deck file of every downloaded language, copies all of the text to an isolate that parses all of it, and gets the whole catalog back; then the UI isolate loops over every card of every deck to build the skill map, and every screen that reads `state.decks` sees every language. The learner looks at one language at a time (the language bar, #461), so almost all of that work is for languages that are not on screen. The decks on `decks-live` are 85.6 MB of YAML in 7,174 files (ja 16.4, sa 10.0, bn 8.2, hi 7.6, gu 6.7, te 6.0, zh 5.7, es 4.3, fr 4.2, mr 3.9 MB); a phone holds the languages (and the native layers) it downloaded, so a learner of six languages pays for six, and the cost grows with every language added.

## 3. Target architecture

### 3.1 The unit: one language's catalog

A **language unit** is everything the catalog holds for one language code `L`:

- its deck files `decks/L/**` as downloaded (cores, layers for the natives on the phone, language files: path, facts, situations, numbers, romanisation, sounds, script guide, topics);
- the shared per-language files `decks/creators/L.yaml` and `decks/recommendations/L.yaml`;
- the files of active private packages whose language is `L` (`private/<id>/...`), including a package that modifies a built-in language;
- the learner-added decks (`added/...`) whose `language.code` is `L`;
- the hidden decks of `L` downloaded from a search result.

A unit is parsed by the existing `DeckCatalog.parseAll`, called on only that unit's files plus the **shared unit**: `decks/themes.yaml` and `decks/sections.yaml` (the bundled copy, replaced by the downloaded one as today, `SharedDeckSource`). Both are at most 512 KB (`maxSharedFileBytes`) and are read on the main isolate and passed as text. The result is a `LanguageCatalog`:

```
LanguageCatalog {
  code, decks, hidden, broken, facts, situations, topics, creators, recommendations,
  numberRules, languagePath, paths (its courses, 'L/native'), sounds, romanisations,
  scriptGuides, scriptFeatures, dataProblems, kindProblems
}
SharedCatalog { themes, sections }
CatalogSet {                       // lib/app/catalog_set.dart, replaces DeckCatalog's role
  shared, directory (the summaries), units: Map<String, LanguageCatalog>,
  Future<LanguageCatalog> ensureLoaded(code), LanguageLoad loadOf(code), int versionOf(code)
}
```

`Catalog` (the type every screen reads today) is kept in P-A to P-C as a **composed view**: `Catalog.compose(shared, loadedUnits)` with the same members, built by concatenating the loaded units' maps and decks. This is why the migration can go consumer by consumer: the old API keeps working over "what is loaded", and a consumer that needs a language that may not be loaded is moved to `ensureLoaded`/the summary (section 5). P-D deletes the composed view.

**Partition check.** The unit loader asserts that every deck in `decks/L/` has `language.code == L`; a mismatch becomes a `BrokenDeck` named "filed under L but teaches M" and is logged. (INFERENCE: the validator already forbids it; F6 found none in the index.)

### 3.2 What runs where, and what crosses

The owner's rule is that nothing of this runs on the UI isolate. The job is:

```
UI isolate                                  worker isolate (Isolate.run, one per unit load)
-----------                                 ----------------------------------------------
ensureLoaded('te')
  paths+SHAs for te from the manifest   -->  LanguageJob { code, root dir, [relative paths + sha],
  shared texts (themes, sections),                         added/private file paths, snapshot path,
  summary stamp, app version                               shared texts, app version, format }
                                             read each file with dart:io (no text on the UI isolate)
                                             read decks-snapshot/te.json, reuse trees whose SHA matches
                                             DeckCatalog.parseAll(files of te + shared)
                                             build the LanguageSummary of te
                                             encode the next snapshot of te (if it changed)
                                        <--  LanguageOutcome { LanguageCatalog, LanguageSummary,
                                                               snapshotText? }   (returned by Isolate.exit:
                                                               transferred, not copied)
UI isolate: store the unit, notify
unawaited: write snapshot and summary (temp file, rename)
```

- **File reads and decode happen in the isolate**: the job carries the directory path and relative paths (strings), never the text. A plain `DiskDeckFiles(root, paths)`, constructible inside an isolate from strings, reads what `FileDownloadedDecks`, `FileDeckStore` and `FilePrivateStore` keep on disk. Where an isolate cannot run (the web build; widget tests) a `MemoryDeckFiles` reads through the `DeckSource` in place, as `parseInPlace` does today; the web build still loads per language (lazily, one `await` per file so the main loop is not held).
- **Only the parsed per-language model crosses back.** It is plain Dart data like today's `Catalog` (`Isolate.run` returns by `Isolate.exit`, which transfers). INFERENCE: transferring a unit costs microseconds, not a copy; the 86 MB of text is never on the UI isolate at all. If a unit contains an object that cannot cross, the existing `try/catch` fallback to in-place parsing stays (`runJobInIsolate`), and the failure is logged once.
- **The job is pure**: no storage, no Flutter, in `lib/core` where it does not need `AppLog` (as `runCatalogJob` is today); `lib/app` only does the file layout and the isolate call.
- **Concurrency.** At most one unit load at a time (a FIFO queue in `CatalogSet`); a load for the selected language jumps the queue; prefetch loads wait for an idle slot (section 3.6). Loads of the same language are joined, as `DeckCatalog.load` joins today.

### 3.3 Snapshots per language (ADR-0048, per language)

`catalog-snapshot.json` (one file, all files' trees, keyed by SHA-256 and `AppInfo.version`) becomes `catalog-snapshots/<code>.json` with the same content for one language: the tree of each of its files and the file's SHA-256, the format version and the app version. A snapshot of another format or version is not used (as ADR-0048). The rules of ADR-0048 stand unchanged: a file's tree is used only if its SHA-256 matches; a missing, damaged or foreign snapshot is no snapshot; a failing parse of a kept tree re-parses from YAML; the write goes to a temporary file and is renamed, off the first screens' path.

What changes is the consequence: **an app update invalidates a language's snapshot only when that language is loaded** (its unit job finds the version differs, parses YAML once, rewrites the snapshot). A language the learner never opens after an update costs nothing. A download that changes `te` rewrites `te.json` only. The old single `catalog-snapshot.json` is read once by the first lazy load that finds no per-language file (to take its trees for that language), then deleted by the junk cleanup (`lib/app/junk_cleanup.dart`) after the per-language files exist, so a learner updating from the old layout does not pay a YAML parse for the selected language.

### 3.4 Summaries: what the screens that list languages read

A `LanguageSummary` is a small JSON record per language on the phone, computed **by the same unit job that parses the language** (so it has one source of truth, the Dart parsers, and counts "as `tools/deck_index.py` counts them" with `countsAsWord`, as `catalogLanguageFromDecks` does today), and stored in one file `language-summaries.json` (all languages, rewritten whenever one entry changes). It is read in full at startup (about 2 to 4 KB per language, **INFERENCE**: 25 languages is under 100 KB) on the worker isolate with the rest of the startup job.

| Field | Used by (section 5 rows) |
|---|---|
| `code`, `info` (the full `LanguageInfo`: iso, name, script, scripts, rtl, tts, icon, typed), `ownName`, `isNotation`, `isSign`, `isIpa` | the language bar and its wheel, the language picker, every screen that lists or names languages (`state.languages`), `languageGlyph` |
| `natives[]` (code, name, deck counts), `courses[]` (per native: unit count, deck count, card count, word count by `countsAsWord`, culture-card count, the `B1Unit` list as `b1Units` makes it: planned, words, milestone, grammar, has) | B1Progress, course lines, the picker's coverage, the Languages page |
| `decks[]` (id, path, native, kind, genre, theme, hidden, adult, card count, `bundled`/`private`) | replaced-deck sets (`placedDecks`), `ownDecks(state.decks).length`, "your decks", reviewer pair lists (`offeredPairs`), language skills sheet |
| `scriptDecks[]` (deck ids that `needsAlphabet`), `hasAlphabet`, `primaryScript`, `formHeardCards[]` (card ids where `Card.hearsForm`: letters, digits, `hears: form`) | the skill map (section 4.2) |
| `hasPath`, `planUnits`, `hasFacts`, `hasSituations`, `hasTopics`, `hasCulture`, `hasRomanisation`, `hasSounds`, `hasNumbers`, `scriptGuideKeys` | the entry points of Today's fact, situations, topics, culture, sound-check, script-check and number drills, so that a button can be drawn or hidden without loading |
| `credits` (deck sources lines, media credit lines, the `ContentCredit` set) | Settings > Sources, which scans every card today (`sourcesOf`, `mediaCreditsOf`, `creditsOf`) |
| `ipaSymbols[]` (only for the `ipa` unit: every answer target and alternative, `ipaAnswerTargets`) | the IPA keyboard, which must offer symbols while a learner types in any language |
| `learnedShare` cache (per course: value, and the `progress.versionOf(L)` stamp it was worked out at) | the picker's "you" percentages (section 4.3) |
| `stamp`: `{ format, filesDigest (SHA-256 over the sorted (path, sha) pairs of the unit's files), app }` | freshness |

**Where it is computed.** Not in the Python index tool: that tool cannot see the phone's actual files (a partial download, the learner's native layers, private and added decks) and would duplicate the parsers' counting rules, which `catalogLanguageFromDecks` already says must match. The index keeps serving the languages **not** on the phone (F13). On the phone the summary is produced by (1) any unit load, and (2) **a download or update of language `L`**: `DeckDownloads.onFilesChanged(language)` (the callback gains the language) enqueues a *summarise* job: the same worker job, with no result kept in memory beyond the summary (the unit is dropped unless it is the selected language). So the summary of a language exists as soon as it is downloaded, before it is ever selected.

**Staleness (stale-while-revalidate).** A summary is **fresh** when its `filesDigest` equals the digest of the manifest's current files for that language and its `format` is current. After an app update the `app` differs: the summary is still **used** (the parsers' output for the fields above changes rarely) but marked `refresh`, and `CatalogSet` queues a background *summarise* job for each such language, one at a time in idle slots, the selected language first (it is loaded anyway). A summary whose `filesDigest` differs (files changed with no summarise run, for example a crash between the move-in of files and the job) is **not trusted**: that language falls back to the index entry (`CatalogLanguage.fromIndex`) until its job has run. `LanguageSummary.format` is raised only when the shape of the record changes; a test compares the summary of a fixed fixture language to a golden, so that a parser change that alters a summary field fails CI and forces a deliberate bump.

### 3.5 The startup path

1. `main()` as today up to `deckDownloads.open()` (F2): the manifest `_onPhone` gives the languages on the phone and the SHA-256 of every file without reading one.
2. **Resolve the startup language without the catalog.** `StartupLanguage.resolve(settings, profile, languagesOnPhone, directory)` mirrors `languageChoices` and `shownLanguage` (`LanguageChoice.options` and `shown`) over the summaries' language list instead of the loaded decks. `_todayScope` already does this for the saved Today summary (F17); this generalises it. INFERENCE: `settings` and the current profile are available before the catalog (`_todayScope` reads both while the catalog loads, F17).
3. One worker job, **startup job**, with: the shared texts, `language-summaries.json`, and the unit job of the startup language (3.2). Output: `CatalogSet` with `shared`, `directory` and one unit. The main isolate reads no deck text.
4. `progress.ready` (the log's replay, already an isolate, ADR-0051), in parallel with step 3 (as today). **The skill map is complete after step 3 from the summaries** (4.2), so `progress.skills` is set once and no unit load ever changes it; INFERENCE: it can even be passed into the open's replay job so that the second, UI-isolate replay of F9 disappears. That is a separate, measurable step of P-B.
5. `status = ready`; the first screens draw from the startup language's unit and the directory. Every other language is `LanguageLoad.notLoaded`.
6. `_afterLaunch` as today (downloads resume, update check). It no longer implies a reload: an update of `L` re-summarises `L` and, if `L` is loaded, reloads that unit only (3.8).

If no language is selected (first launch, nothing downloaded), step 3 loads no unit: only the shared files and the summaries (none yet). If the startup language has no unit (its files were removed), the next language of the options is used.

**Failure.** The startup job never fails the start: a unit that fails to parse as a whole (as opposed to a broken deck, which is a `BrokenDeck` as today) leaves the language `LanguageLoad.failed(error)` with a retry, logged with `describeError`; the app still opens on whatever else works.

#### Cache-first startup (owner, 2026-11-22: "Startup loads only the selected language... from cache... Off the ui thread runs will just verify the data, and only if data is mismatching, the fits will run (also off the ui thread and lazily)")

Startup shows what the cache holds and recomputes nothing when a cache exists. The cache is the per-language snapshot (3.3), `language-summaries.json` (3.4), the skill map (4.2) and the replay snapshot (ADR-0051), each stamped with what it was made from.

1. **Show the cache.** The summaries and the selected language's snapshot are read at once; the learner sees the cached state with no wait on any parse of the decks or replay of the log.
2. **Verify, off the UI isolate, and only verify.** One worker job (`catalog.verify` span) compares each stamp with the phone: the summary's `{format, filesDigest, app}` with the digest of the file manifest's SHA-256s for that language and the running app version, and later the skill-map inputs and the replay snapshot's log stamp. It parses no file and reads no deck text. Its answer is `match` or `mismatch(reason)` (`no summary`, `format changed`, `files changed`, `app updated`) for each language (`verifyLanguageCache`, `CatalogSet.verify`).
3. **Recompute only on a mismatch.** A mismatching language is rebuilt by the unit job in a worker (`catalog.unit.<code>.rebuild` span), lazily and in idle time: the shown language first, the others only when selected or in idle slots. The new unit, summary and snapshot replace the cache, are written back (temporary file, then rename) and are swapped in, so a learner sees no change from a stale but valid cache. After an app update the summary is `refresh`: used as it is while it is rebuilt.
4. **What the stamps cover.** The digest covers the files the downloads' manifest lists. A deck the learner adds or a private package is not in the manifest, so adding one invalidates its language through the catalog (`invalidate`), not through the verify job; this is a known limit of P-A.

### 3.6 Selecting another language

- `AppState.showLanguage(code)` (and a profile switch, a deep link, a reminder tap, a search hit, a language added in the picker) calls `ensureLoaded(code)` first. The language bar's selection is applied **at once** (the bar and the wheel read the directory, which is complete) and the content area shows a **loading state** for the language until its unit is ready: the same skeleton the Decks and Today screens already show while the catalog loads (`CatalogStatus.loading`), scoped to that language (`LanguageLoad.loading`). Nothing blocks input: the bar stays usable, so a learner can swipe on to the next language while the first is loading; the superseded load continues in the background (its result is kept: it is not wasted), and the content shown is that of the language last selected.
- A notification of the load goes through `notifyListeners` marked "keep structure" for every other language (F15), so no other language's cached queue is dropped. `_structureVersion` becomes per language (`structureOf(code)`), bumped by that language's unit changing; the settings and profile bumps stay global. The stamp of F15 gains the unit's version (`catalog.versionOf(code)`).
- Warm selection (the unit has a fresh snapshot): the job reads one small JSON and maps it. Cold selection (new version or changed file): one YAML parse of one language. INFERENCE: sub-second to a few seconds for the largest (ja 16.4 MB on decks-live, of which a learner holds the core plus their native layers); the loading state exists for that case.
- **Prefetch (optional, P-E).** After the first ready frame and an idle period, load the language the learner is most likely to select next: the next language in the bar's order, or the language they last used before the current one, one unit at a time in `Priority.idle` slots (as `lazyFor` schedules Today's other languages, F15 and ADR-0047). Prefetch never starts while a drill session is open or the app is not in the `resumed` lifecycle state. Default off until the startup numbers of P-B are in.
- **Memory.** A loaded unit stays loaded until the app closes (no eviction) by default; a language is up to a few tens of MB of objects (INFERENCE; measured in P-A as the heap size from the Dart VM service in a profile run). If a learner of many languages hits a memory ceiling, an LRU of the last 3 loaded units is the fallback (open question Q4).

### 3.7 Downloads, updates, removals and adds: one unit

`onFilesChanged` becomes `onFilesChanged(language)` (and a `null` for a font-only or shared change). `AppState._filesDownloaded` then:

- shared files changed (themes, sections): reparse the shared unit (small), and mark every loaded unit's theme order stale: `_inTeachingOrder` depends on themes, so reload loaded units that have theme decks (cheap with snapshots: only the shared change), others on their next load;
- language `L` changed: re-summarise `L`; if `L` is loaded, reload `L`'s unit only; keep every other unit and its caches;
- `removeLanguage(L)`: drop `L`'s unit, summary and snapshot; the progress stays by card id (F16);
- an added deck: `DeckStore.save` records the deck's language in `added-index.json` (a few bytes: id to language) so that the partition is known without parsing; a file not in it is routed by a header read (the first lines, as `_headerOf`) in the worker; reload that language's unit only;
- a private package: the package's manifest names its language (`PrivateStore` already keeps one, `lib/app/private_languages.dart:60-80`); reload that language's unit (and the directory entry, since a private language adds an entry to the language list).

### 3.8 The review log for a language that is not loaded

See section 4. In short: the log, the progress index, `versionOf(L)` and the replay snapshot never need the cards; what needs the cards is building a session (needs unit `L`), and the numbers that count *cards* (due counts that must agree with what a session would serve).

## 4. Progress, skills and due counts for languages that are not loaded

### 4.1 What the log gives without any card (FACTS and INFERENCES)

- **FACT** (F16): `ProgressStore` keeps the events with their states, the per-language index and `versionOf(L)` from the log alone; `Abilities.languageOf(cardId)` and `languageOfId(deckId)` give a pair's language from its id. Stats group by language this way and fall back to the id when the catalog lacks the deck (`LanguageTable.of`, `stats_numbers.dart:36-60`).
- **INFERENCE**: therefore these need no unit: streak, days practised, week strip, hours (spent and left are per language from the log; "hours left" needs the plan, which is in the summary's `courses[].units`), answers per language, the how-you-learn fits per language, time per skill, the activity counters, and the **number of pairs due** per language, if "due" is defined by the log.

### 4.2 The skill map from summaries, and the replay that must not repeat

`SkillMap` has three inputs (ADR-0034): `formHeardCards` (card ids), `scriptDecks` (deck ids) and `primaryScripts` (per language). All three are **pure functions of one language's decks and its path**, so the summary stores them (3.4). `CatalogSet.skillMap` is the union over the summaries of the languages on the phone; it is available at startup (3.5, step 3) and **never changes when a unit loads**. It changes only when a language's summary changes (a download, an update): then `progress.skills` is set once.

This fixes a cost that exists even without lazy loading (F9): today every set of `progress.skills` that differs triggers a synchronous full replay on the UI isolate, at every launch and at every `_reloadDecks`. With the map known at startup the replay at open can be given the map (INFERENCE: `replayInIsolate` takes the skills, or is given them, so that its result is already right and `_mapSkills`' assignment is `value == _skills`, a no-op). When a summary does change at run time, the replay should be restricted to that language's events: INFERENCE (to verify in P-B with a test that replays both ways and compares): a language's states depend on the skill map only through its own cards' `formHeardCards`, `scriptDecks` and `primaryScripts[L]`, and on the **log-wide** `lastStudied` only for the parameter choice, which the skill map does not touch. If the verification fails, the fallback is the full replay moved to an isolate (as ADR-0051 does for the open).

The skill map's equality (`SkillMap.==`) compares sets by value (`skill_map.dart:156`): with a union of per-language contributions the comparison costs the size of the union (letters and digits only: INFERENCE, a few hundred ids per language).

## 6. Migration, flag and rollback

- **One flag, two modes.** `CatalogMode { whole, lazy }`, a persisted setting (`settings.catalogMode`, hidden in Settings > Your data > Diagnostics with the log tools, alongside the app log) with the default from a compile-time constant `kLazyCatalogDefault`. `whole` runs the current path through the same `CatalogSet` interface: one unit holding every language, loaded in the worker job, so that even the old path moves the file reads off the UI isolate (the first, nearly risk-free win, in P-A). `lazy` is the new path.
- **Order of defaults.** P-A, P-B ship with `whole` as the default and `lazy` available to the owner's builds (the diagnostics switch). The default flips to `lazy` at the end of P-C, in the same release as the changelog line, after the startup numbers meet section 8. P-D removes `whole` and the composed view and the flag only after one release has shipped with `lazy` as the default and no regression is open.
- **Rollback.** Before P-D: flip `kLazyCatalogDefault` in a patch release, or the learner sets the diagnostics switch; the summaries and per-language snapshots are caches and can be deleted at any time (as ADR-0048 and ADR-0051 say of theirs), and the old single `catalog-snapshot.json` is not deleted until P-D. After P-D: revert the PR that removed the flag.
- **No data migration.** Decks, the review log and the settings are untouched; the two new files (`language-summaries.json`, `catalog-snapshots/`) are caches; `added-index.json` is rebuilt from a header scan if missing.
- **Cache keys.** `DeckCatalog.invalidate` (whole) becomes `CatalogSet.invalidate(code)`; `_structureVersion` becomes per language (F15); every cache keyed on `state.decks` identity is re-keyed on the unit's `version` (a test per cache).

## 9. Open questions for the owner (each with the default the plan takes; do not block on them)

1. **Q1. Is "the language selected" the language bar's language (`shownLanguage`)?** Default: **yes**: `settings.languageChoice`, else the first learned language on the phone, resolved from the directory; no other language is loaded at start.
2. **Q2. Should search ever be global across languages?** Today it is the shown language only (F11). Default: **no change, the shown language only**; a global search would need a per-language trigram file on disk (ADR-0049 builds its index in memory per launch) and is out of this plan.
3. **Q3. Does Today list languages other than the shown one?** Today computes only the shown language since #461; the `lazyFor` machinery serves a profile that lists several. Default: **the shown language only**; the other languages' due counts show from the log without loading, with a tap to load and open.
4. **Q4. Eviction.** Keep a loaded language until the app closes, or keep only the last 3 (LRU)? Default: **keep all loaded**, switch to the LRU only if the profile run shows a memory ceiling.
5. **Q5. How is the picker's "you X%" kept for languages not loaded?** Default: **a stamped cache in the summary, refreshed in the background**; alternative: word-id lists per unit in a sidecar file (exact, larger).
6. **Q6. Due counts of unloaded languages for reminders.** Default: **count from the log and the leech set-asides, without the "card still in the decks" check**, exact once the language is loaded. Alternative: also store a compact set of card-id hashes per language in the summary (larger, exact).
7. **Q7. After an app update, may summaries of unselected languages be used stale until refreshed in idle time?** Default: **yes** (stale-while-revalidate, 3.4); alternative: refresh all before first use (a startup cost equal to today's, which defeats the point).
8. **Q8. Prefetch of the likely next language.** Default: **off** until P-B's numbers are in; then on, idle slots only, never in a session.
9. **Q9. Daily questions for reviewers (`daily_questions.dart`) across courses.** Default: **only the loaded languages' decks**; the set for another course is built when that course is next opened. Alternative: a background load of each reviewer course in idle slots (costs memory and battery).
10. **Q10. A global "every language" leeches list (leeches page with `language == null`).** Default: **list leeches by id with the language name and open the unit on tap**; alternative: remove that entry point. (If `language == null` is reachable at all: the callers are to be checked in P-C2.)
11. **Q11. The flag.** Default: a hidden diagnostics switch plus a compile-time default, removed in P-D; alternative: no learner-visible switch at all, a patch release to roll back.
12. **Q12. Changelog line.** Default: one line at the default flip ("Faster start"); the owner may prefer to name it only after the numbers are known.

## 10. What this plan does not change

Deck format, the deck index schema (the per-language summary is an app cache, not an index field; the index stays the source for languages not on the phone), the download protocol (only the callback gains a language), the review log, FSRS, the replay snapshot format (only its input gains the skill map), the deck validator and tools, and `decks-live`. `lib/core` stays free of Flutter imports; no card id changes.
